# 1.0 Contract Matrix

Status: Active Pre-1.0
Owner: 0disoft

## Classifications

- `stable`: consumers may depend on the named behavior. Breaking changes require a migration note
  and a deprecation window when a compatible transition is possible.
- `experimental`: usable and tested, but field shape, defaults, or adapter behavior may change before
  1.0 with changelog and migration guidance.
- `internal`: implementation detail. Consumers must not parse, generate, or depend on it.

## Package And Runtime

| Surface | Classification | Compatibility promise |
| --- | --- | --- |
| npm package `@0disoft/service-catalog-generator` | stable | Package identity remains public. |
| executable `scg` | stable | Installed package exposes this binary. |
| Node.js 24 minimum runtime | stable | A runtime-floor change is breaking and requires release notes. |
| private workspace packages `@scg/*` | internal | They are not published or supported as consumer imports. |

## Manifest, Config, And Catalog

| Surface | Classification | Compatibility promise |
| --- | --- | --- |
| `scg.service/v1alpha1` | experimental | Strict schema; additions, removals, and promotion to a non-alpha id require migration guidance. |
| `scg.config/v1alpha1` | experimental | Strict keys and defaults; unknown keys fail validation. |
| `scg.catalog/v1alpha1` | experimental | Complete snapshot shape may evolve before promotion. |
| `limits.*` keys and defaults | experimental | Resource failures are stable; numeric defaults remain measurement-driven before 1.0. |
| `validation.minimumServiceCount` | experimental | Defaults to zero; positive values require that many valid, uniquely identified normalized services. |
| `sources[]` adapter ownership | experimental | Roots are explicit, workspace-contained, disjoint after realpath resolution, and never schema-autodetected. |
| explicit `scg-v1` input selection | stable | Native schema remains the default and is never selected by autodetection. |
| explicit `zdp-v2` adapter | experimental | Adapter selection stays explicit; normalized ZDP extension shape may evolve. |
| `extensions.<namespace>` | experimental | Namespaces are retained JSON values but are not interpreted as SCG policy. |

## CLI

| Surface | Classification | Compatibility promise |
| --- | --- | --- |
| commands `scan`, `check`, `report`, `completion` | stable | Names and command purposes remain available. |
| documented flags in `docs/cli/command-contract.md` | stable | Removal or semantic reversal requires deprecation and migration notes. |
| config precedence: flags, config, defaults | stable | Environment variables do not alter catalog policy. |
| exit codes 0 through 5 | stable | Meanings in `docs/cli/output-and-exit-codes.md` remain fixed. |
| diagnostic object fields | stable | `severity`, `code`, and `message` remain; optional location and hint fields keep their meanings. |
| documented diagnostic codes | stable | Codes are not renamed or repurposed without migration guidance. |
| full `--json` snapshot | experimental | Follows the alpha catalog schema. |
| bounded `--summary-json` payload | experimental | Intended for automation; additions may occur before 1.0. |
| human-readable wording and ordering | internal | Consumers must use JSON and diagnostic codes instead of parsing prose. |

## Reports

| Surface | Classification | Compatibility promise |
| --- | --- | --- |
| filenames `catalog.json`, `graph.dot`, `report.html` | stable | Selected formats use these names in the declared output directory. |
| complete-generation replacement | stable | Successful publication never mixes files from different SCG generations. |
| JSON report contents | experimental | Follows `scg.catalog/v1alpha1`. |
| DOT and HTML presentation markup | experimental | Deterministic and escaped, but layout and labels may evolve. |
| `.scg-generation.json` contents | internal | Ownership marker only; consumers must not parse its schema or generation id. |
| `.scg-*` lock, stage, and backup names | internal | Recovery implementation detail with no naming compatibility promise. |

## GitHub Action

| Surface | Classification | Compatibility promise |
| --- | --- | --- |
| root `action.yml` and moving major tag `v0` | stable | Existing major-tag consumers receive compatible pre-1.0 updates. |
| documented inputs and outputs | stable | Names, boolean override semantics, and output meanings remain available. |
| CLI exit propagation | stable | Validation and operational failures remain failures in the Action. |
| Node.js 24 Action runtime | stable | Runtime changes require release notes and hosted smoke evidence. |
| committed `dist/action/index.cjs` implementation | internal | Generated bundle is executable release material, not an import or source API. |

## Diagnostic Codes

The stable code inventory is:

- `adapter.invalid_input`
- `catalog.minimum_service_count`
- `config.invalid`
- `dependency.unknown_target`
- `manifest.duplicate_id`
- `manifest.invalid`
- `manifest.invalid_format`
- `manifest.invalid_schema_version`
- `manifest.invalid_type`
- `manifest.invalid_value`
- `manifest.invalid_yaml`
- `manifest.missing_required_field`
- `metadata.future_review`
- `metadata.stale_review`
- `output.write_failed`
- `path.outside_scan_root`
- `resource.limit_exceeded`
- `security.secret_like_value`

New codes may be added compatibly. Existing codes must not change category or meaning silently.

- Validate resource defaults against additional native consumers, not only the maintained synthetic
  fixture and ZDP catalog.
- Publish the final schema-id migration, deprecation schedule, and supported Action major tag before
